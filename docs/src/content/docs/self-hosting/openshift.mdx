This guide covers running KoAkademy on [Red Hat OpenShift Container Platform (OCP)](https://www.redhat.com/en/technologies/cloud-computing/openshift), Azure Red Hat OpenShift (ARO), or Red Hat OpenShift on AWS (ROSA).

## OpenShift Architectural Considerations

1. **Security Context Constraints (SCC)**:
   - KoAkademy's production image runs `supervisord` to manage FrankenPHP, Inertia SSR, and worker processes, and switches child processes to the `laravel` user (`1000:1000`).
   - Grant the `anyuid` SCC to the deployment's ServiceAccount (`oc adm policy add-scc-to-user anyuid -z default -n koakademy`), or run FrankenPHP directly as an unprivileged entrypoint when enforcing `restricted-v2`.
2. **OpenShift Routes**:
   - OpenShift uses `Route` objects backed by HAProxy routers for ingress traffic and automatic TLS edge termination.
3. **Storage**:
   - For multi-replica setups without S3/R2 object storage, ensure your StorageClass supports `ReadWriteMany` (RWX) for `/app/storage`.

## Step 1: Create Project & Secrets

Create a dedicated OpenShift project:

```sh
oc new-project koakademy --display-name="KoAkademy School System"
oc adm policy add-scc-to-user anyuid -z default -n koakademy
```

Create OpenShift secrets:

```sh
oc create secret generic koakademy-secrets \
  --from-literal=APP_KEY="base64:YOUR_32_BYTE_APP_KEY" \
  --from-literal=DB_PASSWORD="YourSecurePostgresPassword" \
  --from-literal=REDIS_PASSWORD="YourSecureRedisPassword"
```

```yaml

  HORIZON_IN_HTTP_CONTAINER: "false"
  AUTO_MIGRATE: "false"

  # DB & Redis
  DB_CONNECTION: "pgsql"
  DB_HOST: "postgresql"
  DB_PORT: "5432"
  DB_DATABASE: "koakademy"
  DB_USERNAME: "koakademy"
  CACHE_STORE: "redis"
  SESSION_DRIVER: "redis"
  QUEUE_CONNECTION: "redis"

  FILESYSTEM_DISK: "public"
```

Apply the ConfigMap:

```sh
oc apply -f koakademy-configmap.yaml
```

## Step 3: Deploy Gotenberg, PostgreSQL & Redis

Deploy Gotenberg alongside your OpenShift PostgreSQL and Redis services:

```yaml
# dependencies.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: gotenberg
  namespace: koakademy
spec:
  replicas: 1
  selector:
    matchLabels:
      app: gotenberg
  template:
    metadata:
      labels:
        app: gotenberg
    spec:
      containers:
        - name: gotenberg
          image: gotenberg/gotenberg:8
          ports:
            - containerPort: 3000
          resources:
            requests:
              cpu: 200m
              memory: 512Mi
            limits:
              cpu: 1000m
              memory: 1Gi
---
apiVersion: v1
kind: Service
metadata:
  name: gotenberg
  namespace: koakademy
spec:
  selector:
    app: gotenberg
  ports:
    - port: 3000
      targetPort: 3000
```

Apply dependencies (and provision `postgresql` and `redis` via OpenShift operators or StatefulSets):

```sh
oc apply -f dependencies.yaml
```

## Step 4: Release Migration Job

Migrations are a release step, not a container boot. The application is only
started after the schema is prepared.

Create `koakademy-migrate-job.yaml`. The job reads the same configuration and
the same secrets as the application, so it migrates the application database:

```yaml
# koakademy-migrate-job.yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: koakademy-migrate
  namespace: koakademy
spec:
  backoffLimit: 3
  template:
    spec:
      restartPolicy: Never
      containers:
        - name: migrate
          # The same release-specific FrankenPHP tag the application deployment uses.
          image: ghcr.io/yukazakiri/koakademy:v1.30.0-franken
          imagePullPolicy: IfNotPresent
          command: ["php", "artisan", "migrate", "--force", "--no-interaction"]
          envFrom:
            - configMapRef:
                name: koakademy-config
            - secretRef:
                name: koakademy-secrets
```

    type: RollingUpdate

      maxSurge: 1
      maxUnavailable: 0

    matchLabels:
      app: koakademy

    metadata:
      labels:
        app: koakademy

      containers:

## Step 6: Expose OpenShift Route with TLS

Create an edge-terminated OpenShift Route:

```yaml
# koakademy-route.yaml
apiVersion: route.openshift.io/v1
kind: Route
metadata:
  name: koakademy
  namespace: koakademy
  annotations:
    haproxy.router.openshift.io/timeout: "300s"
    haproxy.router.openshift.io/proxy-body-size: "100m"
spec:
  host: koakademy.apps.cluster.example.com
  to:
    kind: Service
    name: koakademy
    weight: 100
  port:
    targetPort: http
  tls:
    termination: edge
    insecureEdgeTerminationPolicy: Redirect
```

Apply Route:

```sh
oc apply -f koakademy-route.yaml
```

## Step 7: Run the Migrations and Verify Deployment

Prepare the schema before the application starts:

```sh
oc apply -f koakademy-migrate-job.yaml
oc -n koakademy wait --for=condition=complete job/koakademy-migrate --timeout=10m
```

The application deployment is only applied once the migration job completed,
so no pod starts against a schema it does not expect:

```sh
oc apply -f koakademy-deployment.yaml
```

Check deployment status:

```sh
oc get pods -n koakademy
oc logs -f deployment/koakademy -n koakademy
```

Open the OpenShift Route URL (`https://koakademy.apps.cluster.example.com/setup`) in your browser to complete installation.

A later release repeats the same step. Remove the finished job first, because
a job name can only be used once:

```sh
oc -n koakademy delete job koakademy-migrate --ignore-not-found
oc apply -f koakademy-migrate-job.yaml
oc -n koakademy wait --for=condition=complete job/koakademy-migrate --timeout=10m
```
