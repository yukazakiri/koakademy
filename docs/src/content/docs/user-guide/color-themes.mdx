# Color themes and appearance

Open **Profile → Personalization → Color Theme** to select an available palette. The selection applies immediately in the React portal and is saved in this browser. Light, dark, and system appearance are separate from the color palette; choose your appearance mode in the same personalization area.

These settings describe the React portal theme provider, not Filament's separate administrative panel styling. Browser preferences do not synchronize between devices or accounts.

## Preview scope

The gallery below documents **pending local theme changes**: six new palettes, updated Caffeine and Claude files, and revised base colors. Those source changes were present in the maintainer's primary checkout when these images were captured, but are not included in this documentation change. Availability in a deployed release depends on its theme catalog and rebuilt assets.

Each image is a Chromium screenshot of an **isolated component preview using the actual CSS variables**, not a screenshot of an authenticated profile or dashboard. The same controls, surfaces, and illustrative chart appear in both modes. Remote fonts are blocked for reproducibility, so typography uses system fallbacks. No student data is shown.

## System defaults and removed themes

A valid saved browser choice takes precedence over the system default. Without a valid choice, the portal uses `defaultColorTheme` from `resources/js/conf/themes.ts`. A removed selection falls back to that system default without saving the fallback as a new personal preference.

Maintainers manage the build-time catalog through [Shadebridge for Laravel](https://github.com/yukazakiri/laravel-shadebridge):

```sh
php artisan theme:import https://tweakcn.com/r/themes/kodama-grove.json
php artisan theme:default kodama-grove
php artisan theme:remove obsolete-theme
npm run build
```

Use `php artisan theme:default --reset` to select the original `default` palette again. Imports and removals change source files; they require a frontend rebuild and deployment, not a browser refresh alone. Never remove an installed theme by deleting only its CSS import.

## Reproduce the screenshots

From the repository root, with Puppeteer and its browser installed:

```sh
node scripts/capture-theme-previews.mjs
```

To capture pending theme files from another checkout without modifying it:

```sh
PUPPETEER_EXECUTABLE_PATH=/usr/bin/chromium \
  node scripts/capture-theme-previews.mjs /path/to/source-checkout
```

The script writes 18 PNGs at 1120 × 720 and `docs/public/images/themes/sources.json`, which records SHA-256 hashes of the exact CSS inputs. The source checkout needs all nine documented palettes and Puppeteer installed. Re-run after changing palette CSS; inspect both modes before committing screenshots.
